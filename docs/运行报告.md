## 五、过程中发现并已固化的两个工程问题

1. **UI 与接口判据分叉的风险**：审批按钮是否渲染、接口是否放行，如果各写一份折扣判断，迟早出现「页面藏了按钮、接口照样能过」。本仓把判据收敛到 `app/policy.py::required_role()`，页面与接口同源调用，并用 `test_workbench_form.py` 反向验证：从页面提交越权请求，同样只能得到 `403`。
2. **跨栈地址错觉**：浏览器在 Windows、服务在 WSL 时，`127.0.0.1` 在两边不是同一个网络栈，固定端口还会让上一轮残留进程冒充本轮服务。已在 `tests/ui/conftest.py` 固定处理：每次取空闲端口 + 服务监听 `0.0.0.0` + 浏览器自动改用 WSL 对外 IP（可用 `PW_BASE_HOST` 覆盖）。

## 六、未做与不做

- 未做并发压测：审批并发正确性靠状态机保证（`status` 非 `pending` 直接 `409`），生产环境建议在审批行上加 `SELECT ... FOR UPDATE`。
- 未接真实企业微信卡片与真实合同服务：以带签名校验的桩替代，替换点见 README 对接待办一节。桩的签名密钥只从环境变量 `WECOM_STUB_SECRET` 读取、**无缺省值**（fail-closed）：未配置时回调直接 500 拒绝，避免用公开桩串伪造审批；`tests/test_rules_and_boundaries.py::test_wecom_secret_is_env_only_fail_closed` 锁住该行为。
- 未覆盖合同签署、账单、佣金结算等招商闭环外围环节，不在本工单验收范围内。
